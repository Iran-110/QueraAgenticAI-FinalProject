# C4w — آمادگی نمایش و کنترل مستقل نسخه

این تحویل، مسیر زندهٔ محدود C4v را برای ارائه خواناتر و قابل بررسی‌تر می‌کند.
مدل، prompt، renderer، recipe، vocabulary، corpus، slotها و مجوز مالی همان
نسخهٔ پذیرفته‌شده‌اند. نتیجهٔ تازهٔ کیفیت مدل یا test نهایی تولید نشده است.

## سه بخش جدا

1. [نمای خواندنی داورها](presentation-view.fa.md): یک صفحهٔ اختیاری روی API
   موجود، فقط با GET؛ برای گفت‌وگو و approval همچنان UI اپراتور لازم است.
   عنوان کوتاه رابط، بازنویسی پاسخ مدل نیست؛ draft و منابع کامل حفظ می‌شوند.
2. [کنترل تکمیلی نسخه](presentation-release-watch.fa.md): inventory بستهٔ
   source و dependencyهای واقعی را جدا از binding مالی ۲۱ فایل بررسی می‌کند.
   ASGI lifespan نیز runها را بیرون lockِ owner می‌بندد؛ متد مستقیم قدیمی
   `PresentationRuntime.close()` بازنویسی نشده است.
3. `scripts/presentation_healthcheck.py`: وضعیت مجوز موجود، ظرفیت واقعی
   نوبت‌ها، source، index فیزیکی، API/SQLite، سلامت UI و فایل‌های ارائه را
   بررسی می‌کند. هیچ پیام، review، مدل، refill یا unhalt اجرا نمی‌کند.

healthcheck به جای «۱۴ منهای تعداد درخواست‌ها»، revision هر پرونده و نوبت‌های
قابل استفادهٔ آن را می‌سنجد. تلاش دومِ مصرف‌نشدهٔ یک نوبت پایان‌یافته، نوبت
تازه محسوب نمی‌شود. وضعیت ledger جلوتر از tracker، حساب نامعتبر، source/index
تغییریافته یا فایل ارائهٔ بدون تأیید بصری، آمادگی را رد می‌کنند.

بررسی index در interpreter جدا با پوشهٔ موقت و محیط محدود انجام می‌شود تا
autoload فایل `.env` توسط dependencyها به فرایند read-only وارد نشود. child
خواندن `.env` و اتصال شبکه را مسدود می‌کند؛ فقط نتیجهٔ ثابت و عمومی برمی‌گردد.

## اجرای بررسی پیش از جلسه

مسیرهای واقعی را از بستهٔ محلیِ همان جلسه بردارید؛ این فرمان authorization
جدید نمی‌سازد و هیچ baseline یا sidecar قبلی را جایگزین نمی‌کند:

```bash
uv run python scripts/presentation_healthcheck.py \
  --protocol /ABSOLUTE/meeting/protocol.json \
  --artifacts /ABSOLUTE/presentation-package \
  --qa /ABSOLUTE/judges-v2-qa.json \
  --watch /ABSOLUTE/meeting/release-watch.json \
  --watch-sha256 REVIEWED_SHA256 \
  --api http://127.0.0.1:8001 \
  --ui http://127.0.0.1:8502 \
  --viewer http://127.0.0.1:8503
```

`operator_ready` فقط نتیجهٔ این کنترل‌ها در همان لحظه است. GET سلامت Streamlit
اتصال درست مرورگر را ثابت نمی‌کند؛ آن بخش جدا در مرورگر بررسی می‌شود. هیچ
provider probe یا امتیاز درستی/مفیدبودن پاسخ در این فرمان وجود ندارد.

## بستهٔ مخصوص داورها

در خروجی مستقل `output/presentation-2026-10-18/`، نسخهٔ v2 شامل ۱۳ اسلاید
فارسی RTL، PDF و source HTML است. موضوع آن مسئله، محصول، داده، نحوهٔ رسیدگی،
کنترل انسان و نتایج قابل دفاع است. متن آزمایش زنده، دستور اجرا و سؤال‌های
احتمالی در PDF اصلی نیستند. یادداشت گوینده و مرجع فنی خصوصی جدا هستند؛ نسخهٔ
v1 و رسید پذیرش C4v دست‌نخورده مانده‌اند.

هر ۱۳ صفحهٔ PDF واقعی با Poppler render و بصری review شده‌اند؛ metadata و hash
سه فایل PDF/HTML/content به همان QA متصل است. کنترل خودکار، جای review بصری
و بررسی مناسب‌بودن محتوا برای مخاطب را نمی‌گیرد.

## حد پذیرش و ادامهٔ تیم

- مجوز جلسه همان pool سه‌پرونده‌ای با ۷ نوبت، حداکثر ۱۴ درخواست و سقف
  ۰٫۱۰ دلار است؛ متن ورودی آزاد است، ظرفیت اجرا آزاد نیست. تمدید خودکار نداریم.
- halt عمومی، سه hold قدیمی و receiptهای تاریخی محفوظ‌اند. C5 به مدرک provider
  نیاز دارد؛ این مسیر آن را حل نمی‌کند.
- کیفیت پاسخ در پذیرش C4v جزئی بود؛ طول پاسخ و ارتباط منابع هنوز محدودیت‌اند.
  تست نرم‌افزار، نقل‌قول دقیق و HTTP200 نمرهٔ کیفیت مدل نیستند.
- native gold، packet و held-out نهایی با مالک evaluation می‌مانند. فایل‌های
  محافظت‌شده برای ساخت این نما یا تنظیم core باز نشده‌اند.
- برای جلسه درخواست‌ها را متوالی بفرستید؛ پیش از stop/restart صبر کنید اجرای
  جاری تمام شود. پس از خطای نامعلوم، retry یا scope جایگزین نسازید.

شاهد نهایی این تحویل در [رسید C4w](receipts/presentation-readiness-2026-10-18.json)
ثبت می‌شود؛ پذیرش واقعی قبلی در [رسید C4v](receipts/presentation-live-acceptance-2026-10-17.json)
باقی است و به اجرای جدید نسبت داده نمی‌شود.
