# برگهٔ کوتاه جلسه — ۱۷ اکتبر ۲۰۲۶

## معرفی در یک دقیقه

«پروژهٔ ما یک دستیار برای بررسی مشکلات Streamlit است. کاربر مسئله را می‌گوید،
agent از منابع نسخه‌دار شاهد می‌گیرد و تصمیم می‌گیرد جواب بدهد، سؤال بپرسد،
جست‌وجوی بیشتری انجام دهد یا پرونده را به maintainer ارجاع دهد.
من core، منطق تصمیم‌گیری و قرارداد اتصال بخش‌ها را انجام دادم.
حسن RAG، بهنام tracker و محمدحسن UI و evaluation را پیش بردند.
پیشنهاد agent از اجرا جداست؛ maintainer باید همان پیشنهاد و revision را تأیید کند.
الان مسیر UI/API/SQLite متصل است و build نهایی RAG را هم مستقل بازسازی کرده‌ایم.
اتصال و رفتار نرم‌افزار تست شده؛ ارزیابی نهایی کیفیت مدل هنوز تمام نشده.»

## چهار نکته‌ای که باید بلد باشیم

| سؤال | پاسخ کوتاه |
| --- | --- |
| چرا single agent؟ | مسئله فعلاً با یک حلقهٔ محدود حل می‌شود؛ برای افزودن framework یا agent تازه، به شاهد نیاز واقعی نیاز داریم. |
| مدل چه می‌کند؟ | در مسیر GroundedPlan، مدل تصمیم و reference را انتخاب می‌کند؛ core متن و نقل‌قول‌های قابل بررسی را می‌سازد و اعتبار ساختاری/منبع/وضعیت را کنترل می‌کند. |
| مدل و بازیابی چیست؟ | recipe فعلی gpt-4o-mini را ثبت کرده؛ Chroma محلی با lexical-hash embedding کار می‌کند. مدل embedding خارجی یا retrieval معنایی را ادعا نمی‌کنیم. |

## چه مشکلی را واقعاً حل کردیم؟

- **Correction:** اگر کاربر نسخه را اصلاح کند، fact جاری عوض می‌شود؛ evidence
  قدیمی برای تصمیم جدید کنار می‌رود و approval تازه برای proposal قبلی معتبر نیست.
- **Approval/Retry:** تأیید به case، revision و خود پیشنهاد وصل است. تأیید
  تازهٔ proposal قدیمی409می‌گیرد؛ retry دقیقِ approval قبلاً موفق همان receipt را برمی‌گرداند و Action دوم نمی‌سازد.
- **Retrieval نسخه‌دار:** نسخه‌های نامناسب می‌توانستند پنجرهٔ candidateها را
  پر کنند. profile اختیاری v2 فیلتر نسخه را پیش از native top-k اعمال می‌کند؛
  post-scope همچنان مرجع نهایی است و default/v1 تغییر نکرده‌اند.
- **ارزیابی قابل دفاع:** شواهد ثابت برای سنجش core از retrieval واقعی و test
  نهایی جداست. همهٔ تلاش‌های ناموفق و نتیجه‌های منفی هم نگه داشته شده‌اند.

## نمایش سه‌دقیقه‌ای

UI محلی: http://127.0.0.1:8501/ — backend پایدار:
http://127.0.0.1:8000/health . این نمایش **scripted/offline** است؛ مدل و RAG
نهایی را نمایش نمی‌دهد. SQLite مخصوص جلسه از ledger بودجه جداست.

1. در **Ask a follow-up question** یک مسئله با نسخهٔ نامعلوم ثبت کن؛ پیشنهاد
   سؤال نسخه را review و approve کن.
2. از فرم **Streamlit version** مقدار `1.50.0` را بفرست.
3. در **Report facts and corrections**، نام `streamlit_version` و مقدار
   `1.49.0` را با پیام توضیحی بفرست؛ fact فعال و revision تازه را نشان بده.
   پیام آزاد به‌تنهایی fact ساختاری را اصلاح نمی‌کند.
4. پیشنهاد را بررسی و تأیید کن؛ ID پرونده را نگه دار و **Open saved case**
   را نشان بده. تست‌های مستقل، stale409 و lost-ACK/retry را پوشش می‌دهند؛
   دکمه یا restart تازه‌ای را که در جلسه انجام نداده‌ای ادعا نکن.

اگر processها بسته شده‌اند، دستور امن دو ترمینال در
[گزارش تحویل](delivery-report.fa.md#نصب-بررسی-و-demo-پایدار) هست.
برای reset از DB تازه استفاده کن؛ ledger بودجه را هرگز reset نکن.

## چه چیزی هنوز باقی است؟

محمدحسن باید native gold و packet را به pinهای v3 و تنظیم نسخه‌دار core وصل
کند؛ freeze منابع، freeze کل اجرای نهایی نیست. C5 به مدرک usage/provider برای
سه درخواست نامعلوم نیاز دارد؛ halt حفظ است و نمایش live را وعده نمی‌دهیم.
Enum، usefulness و پشتیبانی معنایی همهٔ ادعاها هنوز محدودیت دارند؛ سؤال‌های
خارج vocabulary ثابت و تصویر/OCR هم جزو قابلیت‌های آمادهٔ فعلی نیستند.
GitHub Actions به‌علت Billing شروع نمی‌شود؛ verification محلی را CI سبز نمی‌نامیم.
