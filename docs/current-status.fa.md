# وضعیت فعلی و مسیر مطالعه — ۱۸ اکتبر

برای آماده‌شدن جلسه، اصلاح فوری مستقلی در core شناسایی نشده است. نسخهٔ پذیرفته‌شده
را حفظ می‌کنیم و تمرکز روی شناخت پروژه، تمرین روایت و اجرای دمو است. این تصمیم به
معنی کامل‌شدن کیفیت مدل یا ارزیابی نهایی نیست.

## آمادهٔ استفاده در ارائه

- اتصال UI، API، core، Chroma و SQLite، همراه با correction، تأیید قدیمی، restart
  و retry بررسی شده است. [پذیرش واقعی ثبت‌شده](receipts/presentation-live-acceptance-2026-10-17.json).
- build نهایی v3 با ۱۲۲۸ منبع، ۱۸۲۷ chunk و exclusion فریز‌شدهٔ ۹۵ Issue پذیرفته
  شده است. [رسید مستقل build](receipts/final-build-v3-core-acceptance-2026-10-17.json).
- [PDF فعلی ۱۵ اسلایدی](presentation/judges-presentation-fa-v5.pdf)،
  [HTML آن](presentation/judges-presentation-fa-v5.html) و
  [راهنمای گفتاری هماهنگ](presentation/speaker-notes-fa-v5.md) آماده‌اند.
  [QA همین نسخه](presentation/judges-v5-qa.json) از receipt نسخهٔ قبلی جداست.

بررسی خواندنی ۱۸ اکتبر، سرویس‌های جلسه و index فیزیکی را سالم دید؛ هر هفت نوبت
جلسه مصرف‌نشده‌اند. provider در این بررسی فراخوانی نشده؛ سلامت سرویس‌ها تضمین
دسترسی لحظه‌ای provider یا کیفیت جواب اجرای بعدی نیست.

## چه چیزهایی هنوز باز است؟

| مورد | وضعیت و مسئولیت |
|---|---|
| کیفیت جواب | ارتباط برخی شواهد و طول پاسخ‌ها جای بهبود دارد؛ حل Enum تأیید نشده است. این محدودیت در روایت ارائه حفظ شده. |
| ارزیابی نهایی | native gold/packet متصل به pin نهایی و اجرای held-out با محمدحسن می‌ماند؛ نتیجهٔ تحویل‌نشده را ادعا نمی‌کنیم. |
| حساب هزینهٔ C5 | سه درخواست نامعلوم به مدرک usage/charge از provider نیاز دارند؛ halt و holdها برقرارند. |
| آزمایش‌های C4x/C4y/C4z | بررسی پارامتر و منبع خام انجام شده، اما به runtime جلسه منتقل نشده‌اند. review انسانی و اتصال نسخه‌دار، کار اختیاری پس از جلسه است. |

برای بستن موارد باز، build یا watch جلسه را بازنویسی نمی‌کنیم و مجوز مالی تازه
نمی‌سازیم. تنها هنگام یک خطای مشخص و قابل بازتولید، اصلاح اجرایی تازه را بررسی می‌کنیم.

## از کجا بخوانم؟

1. PDF نسخهٔ۵ را یک بار از ابتدا تا انتها بخوان تا تصویر کلی محصول را بگیری.
2. همان ترتیب را با راهنمای گفتاری تمرین کن؛ روایت ۲۹ دقیقه، شامل ۶ دقیقه دمو است.
3. برای چرایی بخش خودمان، [معماری](architecture.md)،
   [تنظیم منتخب core](core-delivery-selection.fa.md) و
   [اتصال build نهایی](final-build-core-acceptance.fa.md) را بخوان.
4. یک بار جای گفتگو، ثبت اطلاعات، correction، منابع و بررسی انسان را در UI پیدا کن.
   تمرین بدون ارسال، ظرفیت جلسه را مصرف نمی‌کند؛ درخواست واقعی تابع runbook موجود است.

PDFهای self-learn قبلی برای یادگیری مفاهیم و تاریخچه مفیدند؛ برای تنظیم فعال،
تعداد منابع، وضعیت تکمیل و نتیجه‌های فعلی، این صفحه و راهنمای نسخهٔ۵ مرجع‌اند.
